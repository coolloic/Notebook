How LLMs & transformers work

Every large language model does one thing: predict the next token. Under the hood it's a transformer — text becomes tokens, tokens become vectors, attention layers mix in context, and the model outputs a probability for every possible next token. Sample one, append it, repeat. That loop, at scale, is everything.

The big idea. An LLM isn't a database of facts or a reasoning engine — it's a very good next-token predictor trained on enormous text. Everything it appears to "know" or "reason" emerges from predicting plausible continuations.

Step 1  Tokens

Models don't see letters or words — they see tokens: common chunks of text (whole words, word-pieces, or characters) from a fixed vocabulary (~50k–200k entries). "tokenization" is roughly "≈ 4 characters" in English, so ~750 words ≈ 1,000 tokens.

Why you care. The context window is measured in tokens (how much the model can see at once), and you're billed per token. Rare words, code and other languages tokenize into more tokens.

Step 2  Embeddings & position

Each token id is mapped to a learned vector (its embedding) — a point in high-dimensional space capturing meaning (see the embeddings guide). Because a plain transformer has no inherent sense of order, a positional encoding is added so the model knows where each token sits in the sequence.

Step 3 · the key idea  Attention

Self-attention is what made transformers work. For every token, the model asks: which other tokens should I pay attention to, to understand this one? It computes a query, key and value for each token; the query·key match decides how much each other token's value contributes. So "it" can attend to the noun it refers to, and a word's meaning is shaped by its whole context.

Multi-head attention runs several of these in parallel, each learning a different kind of relationship (syntax, coreference, topic…). This is the "Attention Is All You Need" mechanism.

In one line. Attention lets every token gather relevant context from the rest of the sequence — that's how the model handles long-range meaning instead of just local word order.

Step 4  The transformer block

One transformer layer = multi-head attention → a feed-forward network → with residual connections and normalization around each. Stack N of these (dozens to over a hundred) and you have the model. The count of all the numbers in these layers is the model's parameters (billions).

input vectors→ attention→ feed-forward→ richer vectors× N layers

Step 5  Predicting the next token

The final layer produces a score (logit) for every token in the vocabulary. Softmax turns those into probabilities, and the model samples one — then appends it and runs the whole pass again for the next token. This one-at-a-time generation is called autoregressive.

Step 6  How it's trained

📚 Pretraining

Predict the next token across a huge text corpus. Errors adjust the parameters (weights) via back-propagation — for a very long time, on many GPUs.

🎯 Fine-tuning / RLHF

Then align it — instruction tuning and reinforcement learning from human feedback teach it to be helpful, follow instructions, and be safe.

The result is a fixed set of weights — the model. It has a knowledge cutoff (it only "knows" what was in its training data) and doesn't learn from your chats unless you add memory or retrieval.

So what  Why it matters for builders

🪟 Context window

Everything the model uses must fit in the token budget — prompt + retrieved data + output.

💸 Tokens = cost & latency

You pay and wait per token. Concise prompts and outputs save both.

🎲 Hallucination

It predicts plausible tokens, not true ones — so ground it (RAG) and verify.

📅 Knowledge cutoff

No live knowledge; use retrieval or tools for fresh/private facts.

The mental model that pays off: treat the LLM as a powerful next-token predictor with a fixed context window and no memory — then everything else in this repo (prompting, RAG, tools, agents, evals) is about feeding it the right context and checking its output.
