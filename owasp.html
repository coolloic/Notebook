OWASP — the Top 10 lists & the security toolbox

OWASP — the Open Worldwide Application Security Project — is a nonprofit community that produces free, vendor-neutral security resources: risk lists, standards, testing guides, cheat sheets and tools. It's the de-facto common language of application security, and you can adopt all of it at no cost.

Beyond the famous Top 10. Most people know OWASP for one list. But its real value is a whole toolbox — a verification standard (ASVS), a testing guide (WSTG), concise cheat sheets, scanners (ZAP), and a maturity model (SAMM) — that together cover the whole software lifecycle.
Companion. This guide catalogues OWASP's resources; for the hands-on defenses (headers, authN/authZ, agent guardrails) see Web · API · AI Security.

The project  What OWASP is

🌍 Open & nonprofit

A global community; every project is free and open, funded by membership & donations — no vendor agenda.

📚 Knowledge + tools

Documentation (Top 10, ASVS, WSTG, cheat sheets) and software (ZAP, Dependency-Check, Juice Shop).

🤝 Community-driven

Local chapters, conferences, and hundreds of contributor-led projects (flagship, production, incubator).

Flagship  The OWASP Top 10 (Web, 2021)

A risk-ranked awareness list of the most critical web-app security risks, refreshed every few years from real-world data. It's an awareness document — a starting point, not a complete checklist (that's ASVS).

#RiskIn a sentence
A01Broken Access ControlUsers act outside their permissions (the #1 risk).
A02Cryptographic FailuresSensitive data unprotected — weak/missing encryption.
A03InjectionUntrusted input runs as code (SQLi, XSS, command).
A04Insecure DesignMissing security by design — no threat modeling.
A05Security MisconfigurationInsecure defaults, verbose errors, open settings.
A06Vulnerable & Outdated ComponentsKnown-vulnerable libraries/dependencies.
A07Identification & Auth FailuresWeak login, sessions, credential handling.
A08Software & Data Integrity FailuresUnverified updates, insecure CI/CD, deserialization.
A09Logging & Monitoring FailuresBreaches go undetected — no logs/alerts.
A10Server-Side Request Forgery (SSRF)Server tricked into calling attacker-chosen URLs.
How to use it. Treat the Top 10 as a baseline awareness & training tool: make sure every category has an owner and a control. Then go deeper with ASVS for verifiable requirements.

Flagship  OWASP API Security Top 10 (2023)

APIs have a distinct risk profile — the theme is authorization, per request and per object.

#RiskIn a sentence
API1Broken Object Level Auth (BOLA)Access another user's object by changing an ID (the #1 API risk).
API2Broken AuthenticationWeak/missing auth on endpoints.
API3Broken Object Property Level AuthOver-exposing or accepting fields (mass assignment).
API4Unrestricted Resource ConsumptionNo rate/size limits → cost blowup & DoS.
API5Broken Function Level AuthRegular users reaching admin functions.
API6Unrestricted Access to Sensitive Business FlowsAutomating a flow (e.g. buy-all-stock) unchecked.
API7Server-Side Request ForgeryAPI fetches an attacker-supplied URL.
API8Security MisconfigurationInsecure defaults, missing hardening.
API9Improper Inventory ManagementForgotten old/undocumented ("shadow") APIs.
API10Unsafe Consumption of APIsTrusting third-party APIs' data blindly.

Flagship  OWASP Top 10 for LLM Applications (2025)

The newest list — the risks unique to apps built on large language models and agents.

#RiskIn a sentence
LLM01Prompt InjectionUntrusted content hijacks the model's instructions (the #1 LLM risk).
LLM02Sensitive Information DisclosureModel leaks secrets, PII or other users' data.
LLM03Supply ChainCompromised models, datasets or plugins.
LLM04Data & Model PoisoningMalicious training/RAG data corrupts behaviour.
LLM05Improper Output HandlingTrusting model output — running it as code/SQL/HTML.
LLM06Excessive AgencyOver-privileged agents taking harmful actions.
LLM07System Prompt LeakageSecrets/logic exposed via the system prompt.
LLM08Vector & Embedding WeaknessesRAG/embedding attacks & cross-tenant leakage.
LLM09MisinformationConfident hallucinations relied upon as fact.
LLM10Unbounded ConsumptionRunaway token cost / denial-of-wallet.
See the defenses. The AI & agent security section covers how to counter prompt injection and excessive agency in practice.

Beyond the lists  The wider toolbox

The Top 10 raises awareness; these turn it into practice:

✅ ASVS

Application Security Verification Standard — hundreds of testable requirements at three levels. Your real security checklist & contract.

🧪 WSTG

Web Security Testing Guide — how to actually test for each vulnerability, step by step.

📄 Cheat Sheet Series

Short, focused how-tos for specific topics (auth, CSRF, input validation, JWT…).

🕷️ ZAP

Zed Attack Proxy — a free, powerful DAST scanner/proxy for finding vulns in running apps.

📦 Dependency-Check / Track

Software Composition Analysis — flags known-vulnerable dependencies (maps to A06).

📈 SAMM

Software Assurance Maturity Model — measure & improve your security program over time.

🧃 Juice Shop

A deliberately-vulnerable app to learn & practise finding the Top 10 safely (great for training/CTFs).

🐉 Threat Dragon

A free threat-modeling tool for the design phase (pairs with A04 Insecure Design).

📱 MASVS / MASTG

The mobile equivalents of ASVS & WSTG for iOS/Android apps.

Put it to work  Using OWASP across the SDLC

Each resource has a natural home in your development lifecycle:

A simple adoption path: train the team on the Top 10 → adopt ASVS as verifiable requirements → test with WSTG + ZAP + Dependency-Check in CI → practise on Juice Shop → track program maturity with SAMM.
